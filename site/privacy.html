Your code stays where you work.

AI SUS is local by default. A Cloud upload is opt-in and contains maps and check results, not source files. Here is the boundary in practical terms.

Local useCloud uploadsControlsThis website

Local use

AI SUS runs your selected coding agent with your account. That agent reads the repository to generate or refresh a map under its own service terms. AI SUS does not make its own AI calls or send code to a AI SUS server for local mapping, viewing, citation freshness, or local pull request checks.

Maps and learning-session state stay in the repository or on your machine unless your team commits a map or explicitly uploads it.

What Cloud can receive

Cloud accepts opted-in maps, related sidecars, check results, and metadata needed to show map and pull request pages. A map is a description of the code. Its labels, prose, and citations can reveal project structure even though the source files are not sent.

MapComponent names, descriptions, connections, and citations that include repository-relative paths and line ranges.
Check resultTouched and stale components, new candidates, architecture rule findings, and related references.
MetadataRepository, branch, commit, focus, selected agent, and run token counts when recorded.
Not acceptedSource files and arbitrary attachments. Upload validation and secret scanning reject unsupported or sensitive content.

Cloud access follows the repository and organization permissions connected through GitHub. Private maps can be shared through expiring, revocable read-only links when that feature is enabled by the team.

What you control

  • Local use works without a AI SUS Cloud account.
  • The CLI and GitHub Action upload only when you enable their Cloud path.
  • Extension sharing requires an explicit enablement and shows the payload before confirmation.
  • Team dashboards aggregate by repository. They do not track or rank individual developers.
  • Enterprise teams can choose a self-hosted deployment.
